## Load it

```ts
import { createArchive, providers } from "@agntn/archives";

const latest = createArchive(providers.commoncrawl());
const pinned = createArchive(providers.commoncrawl({ collection: "CC-MAIN-2023-50" }));
```

## What it lists

Common Crawl publishes one index per crawl. Without `collection`, the provider reads `index.commoncrawl.org/collinfo.json` and uses the newest crawl it advertises; with `collection`, it queries that crawl's CDX API directly. Rows carry `digest`, `mime`, `length` and the `collection` in `_meta`, plus the WARC `filename` and `offset` that locate the body.

A 404 with `No Captures found` is the index's way of saying the URL was never crawled; the provider turns it into an empty listing rather than a failure. Every other 404 keeps meaning failure.

## Reading bodies

`content()` requests the byte range `offset..offset+length` of the WARC file on `data.commoncrawl.org`, gunzips the record and parses the HTTP response inside it. Chunked framing comes off first. Then any `Content-Encoding` the record kept: gzip, deflate (zlib or raw, servers mix those up), brotli or zstd. The result is the original response body, decoded with the charset the record declares.

Common Crawl usually stores the body already decoded and leaves an `X-Crawler-Content-Encoding` note instead. So that last step is for the odd record. Got one in `compress`? You get an error that names it, not a page of noise.

The decoders are plain JavaScript from `@agntn/compressions`. No `DecompressionStream` needed, and each one loads the first time a record asks for it. A gzip read never drags the brotli dictionary along.

## Gotchas

- One crawl is a snapshot in time, not a history. A URL crawled once appears once; for a timeline across years, query several collections or another archive.
- A small `maxBytes` keeps the download small too. The record comes down in doubling slices until one decodes past the cap. A 4 KB read of a 275 KB record stops long before the end.
- `collinfo.json` is fetched on every uncached listing when no collection is pinned. Pin one in services that run for long.
- A lookup can take longer than ten seconds, so Common Crawl waits 60 unless you name a `timeout`. A busy index gives up on its own after about eleven and answers `504 Gateway Time-out`. That's the server, not your deadline.
- The index host is occasionally unreachable; when every archive is asked, that shows up as `commoncrawl: … fetch failed` under `_meta.errors`, and the other providers still answer.
